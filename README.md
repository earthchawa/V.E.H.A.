# V.E.H.A. — Virtual Educational Hangar for Air-cadets

**V.E.H.A.** (Virtual Educational Hangar for Air-cadets) คือห้องเรียนออนไลน์ของโรงเรียนนายเรืออากาศนวมินทกษัตริยาธิราช พัฒนาเองและติดตั้งบนเซิร์ฟเวอร์ภายในสถาบัน ไม่ต้องพึ่งบริการ cloud ภายนอก

เริ่มใช้งานกับนักเรียนสาขาวิทยาการคอมพิวเตอร์ (ประมาณ 20 คนต่อชั้นปี) ก่อน แล้วค่อยขยายไปสาขาอื่น

## สถานะ

| เฟส | ขอบเขต | สถานะ |
|---|---|---|
| **1** | บัญชีผู้ใช้ (รหัสประจำตัว + รหัสผ่าน), ภาคเรียน, รายวิชา, ลงทะเบียน, เอกสารประกอบการสอน | ✅ เสร็จแล้ว |
| **2** | ส่งงาน, กำหนดส่ง, ตรวจความคล้ายระหว่างงาน, หน้า Report แบบ highlight สำหรับอาจารย์และ นนอ. | ✅ เสร็จแล้ว |
| **3** | สมุดคะแนน, หมวดคะแนนแบบถ่วงน้ำหนัก, เกณฑ์ตัดเกรด, หน้าดูผลการเรียน, export CSV, audit log คะแนน | ✅ เสร็จแล้ว |
| **4** | Quiz ออนไลน์ + กันทุจริต (สุ่มข้อ, จับเวลาฝั่ง server, log การสลับหน้าต่าง) และ Safe Exam Browser | ✅ เสร็จแล้ว |
| 5 | ตรวจ plagiarism กับแหล่งภายนอก, รายงานสำหรับผู้บริหาร | |

## เฟส 2: ส่งงานและตรวจความคล้าย

**อาจารย์**
- สร้างงาน กำหนดคำสั่งงาน กำหนดส่ง (เวลาไทย) เลือกได้ว่ารับงานส่งช้าหรือไม่ และเก็บเป็นฉบับร่างก่อนได้
- เปิด/ปิดการตรวจความคล้าย และเลือกว่า นนอ. ดูรายงานของตัวเองได้**ทันที / หลังกำหนดส่ง / ไม่ให้ดู**
- **Starter text:** วางโจทย์หรือโค้ดตั้งต้นที่ทุกคนต้องมี ส่วนนี้จะไม่ถูกนับเป็นความคล้าย
- ตารางงานที่ส่งเรียงตาม % ความคล้าย มีรายการ "คู่ที่คล้ายกันมากที่สุด" และหน้า**เทียบสองชิ้นข้างกัน**พร้อม highlight ส่วนที่ซ้ำ
- กด "ตรวจใหม่" ได้ทุกเมื่อ เช่นหลังแก้ starter text

**นนอ.**
- ส่งงานได้ทั้งพิมพ์คำตอบและแนบไฟล์ (ไม่เกิน 5 ไฟล์ ไฟล์ละ 20 MB) ส่งใหม่ได้จนถึงกำหนดส่ง โดยระบบนับเป็นเวอร์ชัน
- ดู**รายงานความคล้ายของตัวเอง**ได้ เห็นส่วนที่ซ้ำเป็นไฮไลต์ แต่**ไม่เห็นชื่อหรือเนื้อหางานของคนอื่น** แหล่งที่ตรงกันแสดงเป็น "งานของเพื่อน #1, #2"

**วิธีตรวจ** (`src/lib/similarity/`)
- ใช้ k-gram fingerprinting แนวเดียวกับ MOSS/Dolos เทียบงานทุกคู่ในงานเดียวกัน
- **ข้อความ:** ตัดคำด้วย ICU (`Intl.Segmenter`) จึง**รองรับภาษาไทย**ที่ไม่มีเว้นวรรค นับเป็นการซ้ำเมื่อตรงกันติดต่อกันอย่างน้อย 8 คำ
- **โค้ด:** ตัดคอมเมนต์ แทนชื่อตัวแปรเป็น `ID` และ literal เป็น `STR`/`NUM` จึงจับงานที่แค่เปลี่ยนชื่อตัวแปรได้ นับเป็นการซ้ำเมื่อตรงกันอย่างน้อย 23 token
- **ไฟล์ที่ตรวจได้:** ข้อความ (.txt .md …), โค้ด (.py .java .c .cpp .js .ts .go .sql …), PDF, Word (.docx) และ Jupyter (.ipynb) ไฟล์ชนิดอื่นจะเก็บไว้แต่ไม่ได้ตรวจ
- **การบ้านตอบคำถาม:** ระบบไม่นับคำสั่งงานโดยอัตโนมัติ เพราะ นนอ. มักคัดลอกโจทย์ลงในคำตอบ และมีตัวเลือก (เปิดไว้เป็นค่าเริ่มต้น) ให้ไม่นับข้อความที่ซ้ำกันเกินครึ่งชั้น เช่นประโยคจากตำรา ตัวเลือกนี้ทำงานเมื่อมีงานส่งตั้งแต่ 4 ชิ้นขึ้นไป
- **PDF ภาษาไทย:** ไฟล์ที่ใช้ฟอนต์ไทยรุ่นเก่า เมื่อดึงข้อความออกมาสระและวรรณยุกต์มักเพี้ยน ระบบจะตรวจเจอแล้วแสดงว่า "ไม่ได้ตรวจ" แทนการให้คะแนนผิดๆ จึงแนะนำให้ นนอ. พิมพ์คำตอบในช่องหรือส่งเป็น .docx
- **ระดับ:** ต่ำกว่า 15% = ต่ำ, 15–40% = ปานกลาง, 40% ขึ้นไป = สูง ค่าความคล้ายเป็น**สัญญาณให้ตรวจสอบเพิ่ม ไม่ใช่หลักฐานว่าทุจริต**
- **ยังไม่ทำ:** ตรวจกับแหล่งภายนอกหรืออินเทอร์เน็ต ซึ่งต้องใช้บริการเสียเงิน และตรวจว่างานเขียนด้วย AI หรือไม่ ซึ่งความแม่นยำยังต่ำ

## ฟีเจอร์ในเฟส 1

**บัญชีผู้ใช้**
- เข้าสู่ระบบด้วย**รหัสประจำตัว**นักเรียนหรืออาจารย์
- ผู้ดูแลระบบสร้างบัญชีทีละคน หรือ**นำเข้าทั้งชั้นปีจาก CSV** ได้ ระบบออก**รหัสผ่านชั่วคราว**ให้แต่ละคน แสดงครั้งเดียวและดาวน์โหลดเป็น CSV เพื่อพิมพ์แจกได้
- **เข้าสู่ระบบครั้งแรกต้องตั้งรหัสผ่านใหม่**ก่อนใช้งานส่วนอื่น (และใส่อีเมลสำหรับกู้รหัสได้ในขั้นตอนเดียวกัน)
- รหัสผ่านชั่วคราวหมดอายุใน 14 วัน (ตั้งค่าได้ด้วย `TEMP_PASSWORD_DAYS`)
- **ลืมรหัสผ่าน:** รีเซ็ตเองผ่านลิงก์ทางอีเมล ลิงก์ใช้ได้ 30 นาทีและใช้ได้ครั้งเดียว ถ้าไม่ได้ลงทะเบียนอีเมลไว้ ให้อาจารย์หรือผู้ดูแลระบบกด "รีเซ็ตรหัสผ่าน" ซึ่งจะออกรหัสชั่วคราวใหม่ให้
- เปลี่ยนรหัสผ่านหรืออีเมลเองได้ที่หน้า "บัญชีของฉัน"
- กรอกรหัสผิด 5 ครั้งติดกัน บัญชีจะถูกล็อก 15 นาที
- เปลี่ยนหรือรีเซ็ตรหัสผ่านแล้ว อุปกรณ์อื่นที่ล็อกอินค้างไว้จะถูกออกจากระบบทั้งหมด

**ห้องเรียน**
- แยกวิชาตามภาคเรียน (ภาค 1, 2 และฤดูร้อน ปี พ.ศ.) และเลือกดูภาคเรียนย้อนหลังได้
- อาจารย์อัปโหลดไฟล์ (ไม่เกิน 50 MB) หรือแปะลิงก์ (YouTube, Google Drive ฯลฯ) จัดกลุ่มตามสัปดาห์ได้ และซ่อนหรือเผยแพร่ได้
- นักเรียนเห็นเฉพาะวิชาที่ลงทะเบียนไว้ และเห็นเฉพาะเอกสารที่เผยแพร่แล้ว ทุกการดาวน์โหลดต้องผ่านการตรวจสิทธิ์
- ผู้ดูแลระบบจัดการภาคเรียน รายวิชา การเปิดวิชา และรายชื่ออาจารย์/นักเรียนในแต่ละวิชาได้
- บันทึกประวัติการใช้งาน (audit log) ทั้งการเข้าสู่ระบบ การเปลี่ยนรหัสผ่าน และการแก้ข้อมูลของผู้ดูแลระบบ กรองตามประเภท กองวิชา ผู้ใช้ และช่วงเวลา และส่งออกเป็น CSV ได้

### ทำไมรหัสผ่านเริ่มต้นจึงสุ่มต่อคน แทนการใช้รหัสเดียวกันทุกคน

ถ้าทุกคนใช้รหัสเริ่มต้นเดียวกัน (เช่น `123456` หรือวันเกิด) ใครที่รู้รหัสนักเรียนของเพื่อนก็เข้าบัญชีที่เจ้าของยังไม่เคยล็อกอินได้ทันที รวมถึงส่งงานหรือทำ Quiz แทนได้ ระบบจึงสุ่มรหัสชั่วคราวให้แต่ละคน (10 ตัว ไม่มีตัวที่สับสนง่ายอย่าง 0/O, 1/l) แต่ยังทำงานเหมือนรหัสเริ่มต้นทุกอย่าง คือแจกให้นักเรียน แล้วนักเรียนต้องเปลี่ยนเมื่อเข้าสู่ระบบครั้งแรก

## เทคโนโลยี

- **Next.js 16** (App Router, Server Actions) + React 19 + TypeScript + Tailwind CSS 4
- **PostgreSQL 16** ผ่าน Prisma 6
- รหัสผ่านเข้ารหัสด้วย bcrypt (cost 12) ส่วน session token และลิงก์รีเซ็ตเก็บเป็น SHA-256 hash ในฐานข้อมูล
- ไฟล์ที่อัปโหลดเก็บบนดิสก์ของเซิร์ฟเวอร์ (`UPLOAD_DIR`) ใต้ชื่อแบบสุ่ม
- ส่งอีเมลผ่าน SMTP ของสถาบัน (ถ้ายังไม่ได้ตั้งค่า ระบบจะเขียนลิงก์รีเซ็ตลง log ของเซิร์ฟเวอร์แทน)
- Vitest สำหรับ unit test

## พัฒนาบนเครื่อง

ต้องใช้ Node 22+ และ PostgreSQL

```bash
npm install
cp .env.example .env         # แก้ DATABASE_URL และตั้ง COOKIE_SECURE="false" สำหรับ http://localhost
npm run db:deploy            # สร้างตาราง
npm run db:seed:demo         # สร้าง admin + ข้อมูลตัวอย่าง (แสดงรหัสผ่านชั่วคราวในหน้าจอ)
npm run dev                  # http://localhost:3000
```

ข้อมูลตัวอย่างจาก `db:seed:demo` มีภาคเรียน 2/2569, วิชา CS201 และ CS202, อาจารย์ `T0001`, นนอ. `6601001`–`6601005` และงานตัวอย่าง 2 ชิ้นใน CS201 พร้อมงานที่ส่งแล้ว: Lab ภาษา Python ที่มีคนลอกแล้วเปลี่ยนชื่อตัวแปร และเรียงความภาษาไทยที่มีย่อหน้าซ้ำ จึงเปิดดูหน้า Report ได้ทันที ถ้าต้องการสร้างแค่บัญชี admin ให้ใช้ `npm run db:seed`

คำสั่งอื่นที่ใช้บ่อย:

```bash
npm test             # unit tests
npm run typecheck
npm run db:migrate   # หลังแก้ prisma/schema.prisma (สร้าง migration ใหม่)
```

## ติดตั้งบนเซิร์ฟเวอร์ของสถาบัน

ต้องมีเครื่อง Linux ที่ติดตั้ง Docker สเปกขั้นต่ำสำหรับนักเรียนหลักร้อยคนคือ 2 vCPU, 4 GB RAM และดิสก์ตามปริมาณไฟล์

```bash
cp .env.example .env
# แก้: POSTGRES_PASSWORD, APP_URL (เช่น https://classroom.nkrafa.ac.th), SMTP_*
docker compose up -d --build
docker compose exec app npx tsx prisma/seed.ts     # สร้างบัญชี admin ครั้งแรก
```

**สิ่งที่ต้องทำก่อนเปิดใช้งานจริง**
1. **HTTPS:** วาง reverse proxy (nginx หรือ Caddy) ไว้หน้าแอปพร้อมใบรับรอง และปล่อย `COOKIE_SECURE="true"` ไว้ ถ้าต้องใช้ http ภายในเครือข่ายจริงๆ จึงค่อยตั้งเป็น `false`
2. **แบ็กอัป:** ต้องแบ็กอัปทั้ง volume `db-data` (หรือ `pg_dump`) และ volume `uploads` เป็นประจำทุกวัน
3. **อีเมล:** ตั้ง SMTP ของสถาบัน เพื่อให้นักเรียนรีเซ็ตรหัสผ่านเองได้
4. **อัปเดตเวอร์ชัน:** สั่ง `git pull && docker compose up -d --build` แล้ว migration จะรันอัตโนมัติตอนแอปเริ่ม

## เฟส 3: สมุดคะแนนและเกรด

- **หมวดคะแนนพร้อมน้ำหนัก** เช่น งาน 40% / กลางภาค 25% / ปลายภาค 35% ถ้าไม่ตั้งหมวด ระบบจะคิดคะแนนรวม = คะแนนที่ได้ ÷ คะแนนเต็ม
- **รายการคะแนน:** ผูกกับงานที่มอบหมายได้ โดยใส่ "คะแนนเต็ม" ในฟอร์มสร้างงาน หรือสร้างเป็นรายการแยก เช่นคะแนนสอบหรือคะแนนจิตพิสัย
- **ตารางกรอกคะแนน:** ระบบคำนวณ % รวมและเกรดทันทีขณะพิมพ์ ช่องที่แก้แต่ยังไม่บันทึกจะเป็นสีฟ้า ถ้าใส่คะแนนเกินคะแนนเต็มจะบันทึกไม่ได้ และกด Enter เพื่อเลื่อนลงแถวถัดไปได้
- **ช่องว่างไม่ถูกนับ** (ยังไม่ให้คะแนน) ถ้า นนอ. ไม่ส่งงานให้ใส่ 0
- **ให้คะแนนจากหน้า Report:** อาจารย์ดูความคล้ายแล้วให้คะแนนพร้อม feedback ได้ในหน้าเดียวกัน
- **เผยแพร่ทีละรายการ:** นนอ. เห็นเฉพาะรายการที่เผยแพร่แล้ว พร้อม feedback, % ของแต่ละหมวด, % รวม, เกรด และ GPA โดยอาจารย์ปิดไม่ให้ นนอ. เห็นคะแนนรวมได้
- **เกณฑ์ตัดเกรด:** ค่าเริ่มต้นคือ A ≥ 80, B+ ≥ 75, B ≥ 70, C+ ≥ 65, C ≥ 60, D+ ≥ 55, D ≥ 50, F แก้เองได้ทีละวิชา
- **Export CSV** สำหรับส่งงานทะเบียน รองรับภาษาไทยใน Excel
- ทุกการแก้คะแนนบันทึกลง audit log ว่าใครแก้ เมื่อไร จากเท่าไรเป็นเท่าไร

## เฟส 4: Quiz ออนไลน์

**อาจารย์**
- **คำถาม 4 แบบ:**
  - ปรนัยตอบข้อเดียว (มีปุ่มสร้างแบบถูก/ผิดในคลิกเดียว)
  - ปรนัยตอบได้หลายข้อ: ให้คะแนนบางส่วน = (ข้อที่เลือกถูก − ข้อที่เลือกผิด) ÷ จำนวนข้อที่ถูก และไม่ติดลบ
  - คำตอบสั้น: ระบบตรวจอัตโนมัติเมื่อตรงกับคำตอบที่ยอมรับ (ไม่สนตัวพิมพ์ใหญ่-เล็กและช่องว่าง) ถ้าไม่ตรงให้อาจารย์ตรวจ
  - อัตนัยหรือเขียนโค้ด: อาจารย์ตรวจ
- ตั้งช่วงเวลาเปิด-ปิดสอบ เวลาทำ สุ่มลำดับข้อและตัวเลือก และเลือกว่าหลังปิดสอบ นนอ. เห็นอะไร (ไม่เห็น / เห็นคะแนน / เห็นคะแนน คำตอบ และ feedback)
- **ตรวจทีละข้อทั้งชั้น** (เหมือนตรวจกระดาษข้อ 3 ของทุกคน) หรือตรวจทีละคนก็ได้ และแก้คะแนนที่ระบบตรวจอัตโนมัติได้
- ถ้าแก้เฉลยหลังมีคนทำแล้ว ระบบคิดคะแนนอัตโนมัติใหม่ให้ แต่คะแนนที่อาจารย์ให้เองจะไม่ถูกเปลี่ยน
- คะแนนเข้าสมุดคะแนนอัตโนมัติเมื่อตรวจครบทุกข้อ
- ถ้าเครื่องของ นนอ. มีปัญหา กด "ให้ทำใหม่" ได้

**นนอ.**
- หน้าสอบแยกจากเมนูปกติ มีตัวนับเวลา บันทึกคำตอบอัตโนมัติ และถ้าเน็ตหลุดหรือปิดหน้าไปแล้วกลับมา ทำต่อได้
- เวลาจับฝั่ง server และระบบส่งคำตอบให้อัตโนมัติเมื่อหมดเวลา
- ระบบไม่ส่งเฉลยไปยังเบราว์เซอร์

**กันทุจริต**
- **บันทึกเหตุการณ์ให้อาจารย์ดู:** ออกจากหน้าต่าง, สลับแท็บ, ออกจากโหมดเต็มจอ, copy/paste/คลิกขวา (ถูกบล็อกด้วย), โหลดหน้าใหม่ และทำต่อจากอุปกรณ์หรือ IP อื่น
- **บังคับใช้ Safe Exam Browser:** ใส่ Config Key จาก SEB Config Tool เพื่อให้ระบบตรวจ header `X-SafeExamBrowser-ConfigKeyHash` ถ้าไม่ใส่ ระบบตรวจแค่ User-Agent ของ SEB ซึ่งปลอมได้ง่ายกว่า ในหน้าตั้งค่ามี Start URL ให้คัดลอกไปใส่ใน SEB
- **จำกัดเครือข่าย:** ใส่ IP หรือ CIDR ของ Wi-Fi ห้องสอบ
- ระบบกันได้เฉพาะสิ่งที่เกิดบนจอ **การสอบยังต้องมีผู้คุมในห้อง** เพราะกันโทรศัพท์หรือการถามเพื่อนไม่ได้

## โครงสร้างสถาบันและสิทธิ์

- **กองวิชา (Department) → สาขาวิชา (Subject area) → รายวิชา:** ผู้ดูแลระบบจัดการได้ที่เมนู "กองวิชา/ภาควิชา" เช่น กองวิชาคณิตศาสตร์และคอมพิวเตอร์ที่มีภาควิชาวิทยาการคอมพิวเตอร์และภาควิชาคณิตศาสตร์
  - กำหนดภาควิชาให้รายวิชาได้ที่หน้า "ภาคเรียนและวิชา" และให้บุคลากรได้ตอนสร้างบัญชี หรือผ่านคอลัมน์ที่ 5 ของไฟล์ CSV
  - หน้าแรกจัดกลุ่มการ์ดวิชาตามภาควิชา และหน้าผู้ใช้กรองตามภาควิชาได้
- **สิทธิ์แก้คะแนนเป็นของอาจารย์ผู้สอนวิชานั้นเท่านั้น** ครอบคลุมสมุดคะแนน การให้คะแนนในหน้า Report และการตรวจ Quiz ผู้ดูแลระบบดูและ export ได้อย่างเดียว ส่วน นนอ. เห็นเฉพาะคะแนนของตัวเองที่เผยแพร่แล้ว
- **ตั้งค่าการสอบระดับสถาบัน (ผู้ดูแลระบบ):**
  - ห้องสอบพร้อมช่วง IP ของแต่ละห้อง
  - Config Key ของ Safe Exam Browser และ Start URL สำหรับฝ่าย IT
  - อาจารย์แค่เลือกว่า "เบราว์เซอร์ปกติ / โหมดล็อกเครื่อง" และ "ที่ไหนก็ได้ / เฉพาะห้องที่เลือก" ไม่ต้องรู้เรื่อง IP หรือคีย์

## การใช้งาน

- เพิ่มหรือสร้างเอกสาร งาน แบบทดสอบ ข้อสอบ ผู้ใช้ ภาคเรียน และวิชา ผ่านหน้าต่าง Popup (กด Esc หรือคลิกนอกหน้าต่างเพื่อปิด)
- ลากไฟล์มาวางได้ทั้งตอนอัปโหลดเอกสาร ส่งงาน และนำเข้า CSV
- เรียงลำดับข้อสอบด้วยการลาก (หรือปุ่ม ↑↓ สำหรับคีย์บอร์ด)
- หน้าแรกมีแผง "สำหรับคุณ" ที่แยกจากการ์ดวิชาชัดเจน และแต่ละวิชามีสีประจำตัว (คำนวณจากรหัสวิชา) ซึ่งใช้ตรงกันทุกหน้า

## อาจารย์ที่สอนหลายวิชาหรือหลายกลุ่มเรียน

- **ใช้บัญชีเดียวต่ออาจารย์หนึ่งคน** ผู้ดูแลระบบเพิ่มอาจารย์เป็นผู้สอนในแต่ละวิชาหรือกลุ่มเรียน สิทธิ์แยกตามวิชาอยู่แล้ว
- **หน้าแรกของอาจารย์มีแผง "งานที่ต้องจัดการ"** รวมทุกวิชาที่สอนในเทอมนั้น แสดงงานรอให้คะแนน งานที่ความคล้ายสูง (≥ 40%) และงานที่ใกล้ถึงกำหนดภายใน 7 วันพร้อมจำนวนที่ส่งแล้ว
- **หน้าแรกของ นนอ. มีแผง "ใกล้ถึงกำหนดส่ง"** แสดงงานที่ยังไม่ส่งในทุกวิชา เรียงตามกำหนดส่ง
- **วิชาที่มีหลายกลุ่มเรียน** (เช่น CS201 กลุ่ม 1 และ 2)
  - ตอนสร้างเอกสารหรืองาน ติ๊ก "เพิ่มไปยังกลุ่มอื่นด้วย" ได้
  - ของที่มีอยู่แล้วกด "คัดลอกไปกลุ่ม…" ได้
  - สมุดคะแนนมีปุ่มคัดลอกการตั้งค่า (หมวด น้ำหนัก เกณฑ์ตัดเกรด และรายการคะแนนสอบ)
  - ระบบ**ไม่คัดลอกงานที่ส่ง รายชื่อ และคะแนน** และไฟล์ที่คัดลอกจะเป็นสำเนาแยกของแต่ละกลุ่ม
  - ป้าย "Sec N" จะแสดงเมื่อวิชานั้นมีมากกว่าหนึ่งกลุ่ม

## Demo บน Vercel (สำหรับทดลองใช้)

ใช้สำหรับเปิดให้คนลองใช้ก่อนติดตั้งจริงในสถาบัน **อย่าใส่ข้อมูลจริงของ นนอ.** เพราะเป็นเว็บสาธารณะและบัญชี demo ใช้รหัสผ่านเริ่มต้นเดียวกัน

1. ไปที่ [vercel.com/new](https://vercel.com/new) → **Import** repo `nkrafa-ai-classroom`
2. ในหน้า Configure เพิ่ม Environment Variables:
   - `DEMO_SEED` = `true`
   - `DEMO_PASSWORD` = รหัสผ่านเริ่มต้นของบัญชี demo (ตั้งเองได้)
3. กด **Deploy** ครั้งแรกจะ build ไม่ผ่านเพราะยังไม่มีฐานข้อมูล ซึ่งเป็นเรื่องปกติ
4. เข้าโปรเจกต์ → **Storage** → **Create Database** → **Neon** (เลือก region Singapore) → **Connect** กับโปรเจกต์ ระบบจะตั้ง `DATABASE_URL` และ `DATABASE_URL_UNPOOLED` ให้อัตโนมัติ
5. **Deployments** → **Redeploy**
6. เปิด `https://<ชื่อโปรเจกต์>.vercel.app` แล้วเข้าสู่ระบบด้วย `admin`, `T0001` หรือ `6601001`–`6601005` พร้อม `DEMO_PASSWORD` ระบบจะให้ตั้งรหัสใหม่ตอนเข้าครั้งแรก

สิ่งที่ระบบปรับให้อัตโนมัติเมื่อรันบน Vercel:
- ไฟล์อัปโหลดเก็บใน Postgres (`STORAGE_DRIVER=db`) เพราะ Vercel ไม่มีดิสก์ถาวร
- จำกัดอัปโหลดไม่เกิน 4 MB ต่อครั้ง เพราะ Vercel รับ request ได้สูงสุด 4.5 MB ระบบเช็กในเบราว์เซอร์ก่อนส่ง
- `scripts/vercel-build.ts` รัน migration ผ่าน connection ตรง (unpooled) แล้ว seed ข้อมูล demo (รันซ้ำได้โดยไม่สร้างข้อมูลซ้ำ) แล้วจึง build
- `vercel.json` ตั้ง region เป็น `sin1` (สิงคโปร์) ให้ใกล้ประเทศไทย

## โครงสร้างโค้ด

```
prisma/schema.prisma          โครงสร้างฐานข้อมูล
prisma/migrations/            migration (commit ทุกครั้งที่แก้ schema)
prisma/seed.ts                สร้าง admin / ข้อมูลตัวอย่าง
src/lib/auth/                 รหัสผ่าน, session, ล็อกบัญชี, reset token
src/lib/access.ts             ตรวจสิทธิ์ต่อวิชา (manage / view)
src/app/login, change-password, forgot-password, reset-password
src/app/(app)/                หน้าที่ต้องล็อกอิน: แดชบอร์ด, วิชา, บัญชี, admin
src/app/api/materials/[id]/download   ดาวน์โหลดไฟล์ (ตรวจสิทธิ์ทุกครั้ง)
```
